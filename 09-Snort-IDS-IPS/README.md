# Snort IDS/IPS Detection & Prevention Lab

## Overview

Hands-on Snort IDS/IPS exercises completed during CSA training in a controlled virtual lab environment. The sessions focused on network traffic monitoring, packet logging, IDS configuration, custom detection rules, alert analysis, and inline IPS blocking.

## Objectives

- Understand Snort IDS and IPS functionality
- Monitor network traffic using Snort
- Capture and log packets
- Configure Snort for IDS operation
- Analyze Snort alerts
- Create custom detection rules
- Detect ICMP traffic
- Detect SSH connection attempts
- Test detection against Nmap and authentication activity
- Configure Snort for inline IPS operation
- Validate traffic blocking

## Lab Environment

The exercises were performed in a controlled virtual lab environment using Snort and Kali Linux.

## Snort Modes Practiced

### 1. Sniffer Mode

Used Snort in sniffer mode to observe live network traffic.

Activities included:

- Monitoring traffic on the network interface
- Generating ICMP traffic using ping
- Observing packets in real time
- Identifying source and destination information

### 2. Packet Logging Mode

Configured Snort to capture and log network packets.

The captured traffic was saved and later analyzed using Wireshark.

This helped connect Snort packet logging with packet-level network analysis.

## IDS Configuration

Configured Snort as an Intrusion Detection System.

The configuration included:

- Reviewing the Snort configuration file
- Identifying the `HOME_NET` variable
- Reviewing Snort rule locations
- Enabling and disabling rules
- Working with `local.rules`
- Monitoring alerts generated by network activity

## Nmap Detection

Generated Nmap scanning activity against a controlled lab target.

Snort detected the scanning traffic and generated IDS alerts.

This demonstrated how network reconnaissance can produce detectable security events.

## Custom ICMP Detection Rule

Created a custom Snort rule to detect ICMP traffic.

The rule included:

- ICMP protocol
- Source and destination network configuration
- Custom alert message
- Rule SID
- Rule revision
- Alert priority

The rule was added to `local.rules` and tested by generating ICMP traffic with ping.

Snort successfully generated an alert when the traffic matched the rule.

## Custom SSH Detection Rule

Created a custom Snort rule to detect SSH connection attempts.

The rule monitored TCP traffic directed toward port 22 and generated an alert when matching activity was observed.

The rule was tested using:

- SSH connection attempts
- Controlled authentication testing
- Medusa authentication activity

Snort generated alerts for the matching SSH activity.

## IPS Configuration

Configured Snort for inline IPS operation.

The SSH detection rule was modified to use a blocking action instead of only generating an alert.

The IPS configuration was tested by attempting an SSH connection from Kali.

The connection was reset when the traffic matched the configured IPS rule, demonstrating active traffic prevention.

## Detection Workflow

The lab followed a basic SOC detection workflow:

1. Generate controlled network activity
2. Capture and inspect traffic
3. Configure Snort rules
4. Generate matching activity
5. Review Snort alerts
6. Analyze source and destination information
7. Validate the detection
8. Convert detection logic into prevention using IPS
